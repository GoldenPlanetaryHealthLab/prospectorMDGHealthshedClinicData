Tip Procedure: Declare The Parquet Transformation Boundary

Declare the shared file-to-file transformation used by this page and by the clinic-month inventory. Each caller supplies its dependencies and output path.

The helper below opens Parquet inputs with automatic materialization into R disabled, applies the supplied transformation, and writes the result through DuckDB. Only the output path crosses the target boundary. Input paths, output paths, and transformation dependencies stay explicit at each call site.

s0_pipeline_parquet_transform_fn <- function(
  input_paths, output_path, transform, read_options = list()
) {
  input_paths <- unname(as.character(input_paths))
  stopifnot(
    length(input_paths) > 0L,
    all(file.exists(input_paths)),
    length(output_path) == 1L, !is.na(output_path), nzchar(output_path),
    is.function(transform)
  )

  relation <- duckplyr::read_parquet_duckdb(
    input_paths,
    prudence = "stingy",
    options = read_options
  )
  result <- transform(relation)

  dir.create(dirname(output_path), recursive = TRUE, showWarnings = FALSE)
  duckplyr::compute_parquet(result, output_path)
  output_path
}
Tip Procedure: Read One Raw RMA File With Explicit Types

In this first section of the script, we take raw files and prepare them by aggregating them into a tracked Parquet file, one row per clinic-year-month, and one column per health outcome-age-sex.

Applies only to 2020-2022 data.

We’ve also opted-in to using DuckDB via the duckplyr package to avoid in-memory limitations.

We have a variable number of missing values in our first rows of data, so we’ll need to ensure they don’t get read as logical NAs. The duckplyr options list allows us to force DOUBLE and VARCHAR types:

The archived CSVs also use literal NA for missing values. The legacy readr::read_csv() reader recognizes both empty fields and NA as missing; set DuckDB’s nullstr explicitly to preserve that rule before converting measurements to DOUBLE. Otherwise row-count diagnostics can succeed while the Parquet write fails when it evaluates the measurement columns. Missing values remain null, including in entirely missing numeric columns.

s0_clinic_RMA_read_nonlogical_fn <- function(filepath){

  readr_spec <- spec_csv(filepath) 
  spec_names <- names(readr_spec$cols)

  readr_spec %>%
    as.character() %>%
    str_split_1("") %>%
    tibble(spec = .) %>%
    mutate(
      name = spec_names,
      duckdb_dtype = case_when(
        str_detect(name, regex("description", ignore_case = TRUE)) ~ "VARCHAR",
        spec == "c" ~ "VARCHAR",
        spec == "d" ~ "DOUBLE",
        spec == "l" ~ "DOUBLE",
        .default = "DOUBLE"
      )
    ) %>%
    select(name, duckdb_dtype) %>%
    deframe() -> duckdb_spec

  
  # Set the CSV dialect explicitly. Auto-detection samples only the first
  # rows, so a quoted comma appearing later can otherwise be misclassified as
  # an extra column.
  read_csv_duckdb(
    filepath,
    options = list(
      types = list(duckdb_spec),
      nullstr = list(c("", "NA")),
      delim = ",",
      quote = "\"",
      escape = "\""
    )
  ) %>%
    return()
  
}
Tip Procedure: Declare The Clinic-Month Maximum Reduction

Define the reducer shared by the per-file and cross-file aggregation stages. Missing grouping keys fail before a result can be written.

The reductions below use operations that duckplyr translates to DuckDB. DuckDB’s MAX() ignores null values and returns null for an all-null group, which preserves the behavior of the previous max_or_na() helper without materializing columns in R.

s0_clinic_RMA_summarise_group_max_fn <- function(df) {
  grouping_columns <- c("organisationunitid", "periodname")
  missing_grouping_columns <- setdiff(grouping_columns, names(df))
  if (length(missing_grouping_columns)) {
    stop(
      "Cannot calculate clinic-month maxima; missing grouping column(s): ",
      paste(missing_grouping_columns, collapse = ", ")
    )
  }

  df |>
    summarise(
      across(
        -all_of(grouping_columns),
        ~ max(.x, na.rm = TRUE)
      ),
      .by = all_of(grouping_columns)
    )
}
Tip Procedure: Write One Reduced Parquet Branch

Read one source file, remove redundant columns, compute its clinic-month maxima, and write the branch artifact. The small row-count diagnostics are collected for the execution log; the measurement table stays in DuckDB.

s0_clinic_RMA_process_csv_fn <- function(csv_path, output_path=here("data/intermediates"), drop_cols = c("organisationunitcode", "organisationunitdescription")) {
  stopifnot(length(csv_path) == 1L, file.exists(csv_path))
  
  cli_alert_info(paste("Working on:", csv_path))
  
  # Read file with type-safe reader
  temp_df <- s0_clinic_RMA_read_nonlogical_fn(csv_path)
  
  # Drop the extra columns if they exist
  temp_df <- temp_df %>%
    select(-any_of(drop_cols))
  
  # Calculate diagnostics in DuckDB and collect only the two scalar results.
  file_stats <- temp_df |>
    summarise(
      group_rows = n(),
      .by = c(organisationunitid, periodname)
    ) |>
    summarise(
      rows = sum(group_rows),
      duplicate_rows = sum(group_rows - 1L)
    ) |>
    collect()

  cli_alert_info(paste(
    "Successfully created dataframe for", csv_path, "with shape",
    file_stats$rows[[1]], "x", length(names(temp_df))
  ))
  cli_alert_info(paste(
    "Number of duplicate clinic-month-year records:",
    file_stats$duplicate_rows[[1]]
  ))
  
  # Description fields are assigned VARCHAR when the CSV relation is created.
  result = s0_clinic_RMA_summarise_group_max_fn(temp_df)
  
  dir.create(dirname(output_path), recursive = TRUE, showWarnings = FALSE)
  compute_parquet(result, output_path)

  output_path
}

s0_clinic_RMA_process_csv_fn() intentionally accepts exactly one path, and never holds other input tables in memory. _targets.R selects the RMA_W3_FULL paths in s0_clinic_RMA_W3_raw_paths_chr, then declares one file-tracking branch per path in s0_clinic_RMA_W3_raw_csv. The Parquet writer maps over those tracked file branches outside this notebook. That makes each CSV independently schedulable and means the branch artifacts contain parquet files rather than raw csvs. Dynamic branching enables parallel execution; the approved Slurm allocation and selected targets backend determine how many branches run concurrently.

The second reduction in _targets.R combines the smaller branch summaries and takes the clinic-month maximum again. This is equivalent to taking the maximum over the fully combined raw data because maximum is associative:

[ () = ((), , ()) ]

This two-stage reduction was introduced after the raw-table aggregation was OOM-killed with a 120 GiB Slurm allocation. It is a memory-scaling change, not a change to the numeric maximum rule. The current reducer retains the prior rule for every non-grouping field; a later curation decision should define field-specific behavior for names, descriptions, and codes rather than treating a lexicographic character maximum as scientific metadata.

WarningWhy aggregation stays in DuckDB

The per-file reductions completed, but the final target was OOM-killed in a 120 GiB Slurm allocation. The diagnostic evidence is that files can have zero duplicate clinic-month keys. In that situation, a per-file group maximum has nearly the same cardinality as the input, so the previous R-based final target needed to materialize all branch summaries at once. Increasing the requested memory is not the next proposed experiment.

The per-file target now implements a disk-backed DuckDB/duckplyr boundary. Its stages are:

  1. preserve the existing one-file CSV reading, UTF-8, and type-normalization behavior;
  2. execute each per-file clinic-month MAX reduction in DuckDB;
  3. write each branch result to Parquet without materializing it in R.

The final target below reads all branch Parquet paths as one DuckDB relation, executes the final clinic-month reduction, and persists that result through another file target.

The aim is to preserve the original code’s transformation logic as closely as possible. The change is the execution engine and storage boundary, not a redesign of the data-cleaning rules. Before implementation, the output schema and reducer for metadata fields must be made explicit: numeric measures use maximum, whereas names, descriptions, and codes require a domain-specific rule. DuckDB and duckplyr are declared runtime dependencies.

Tip Procedure: Write The Cleaned Wave 3 Table

Use the descriptive crosswalk and the reviewed period-specific substitutions to produce the cleaned Parquet artifact.

Lastly, we left_join the RMA wave 3 data with this crosswalk on Organisation. The last bit of cleaning correctly maps diagnoses that changed names slightly between wave 3 subwaves

#| format: file
s0_clinic_RMA_W3_clean_parquet <- s0_pipeline_parquet_transform_fn(
  input_paths = s0_clinic_RMA_W3_group_max_parquet,
  output_path = here("data/intermediates/clinic_RMA_W3_clean.parquet"),
  transform = function(relation) {
    relation |>
      left_join(as_duckdb_tibble(s0_gesis_xwalk_nonmissing_uid_df), by = "organisationunitid") |>
      mutate(
        # rows of AME where periodcode > 202300 should be values of AME prem;
        `T13: AME 0-6 mois` = if_else(
          periodcode > 202300,  `T13: AME premiere heure 0-6 mois`, `T13: AME 0-6 mois`
        ),
        # etc
        `T13: AME 1ère heure` = if_else(
          periodcode > 202300, `T13: AME premiere heure 1ère heure`, `T13: AME 1ère heure`
        ),
        `MIDs pour groupe à risque (migrants/réfugiés/personnes déplacées)` = if_else(
          periodcode > 202300, `CHU CHRR T26 MIDs pour groupe à risque (migrants/réfugiés/personnes déplacées)`, `MIDs pour groupe à risque (migrants/réfugiés/personnes déplacées)`
        )
      ) |>
      # remove redundant
      select(
        -any_of(c(
          "T13: AME premiere heure 0-6 mois",
          "T13: AME premiere heure 1ère heure",
          "CHU CHRR T26 MIDs pour groupe à risque (migrants/réfugiés/personnes déplacées)"
        ))
      ) |>
      mutate(V1 = row_number() - 1L) |>
      select(V1, everything())
  }
)

Important: there is a chance that the assignment of V1 to row number doesn’t work here, due to the fact that the data is now in a Parquet and row numbers are only computed at evaluation time.
