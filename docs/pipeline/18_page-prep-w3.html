Tip Procedure: Prep Raw RMA_DEPSI Files

In this first section of the script, we take raw files and prepare them by aggregating them into a single CSV, one row per clinic-year-month, and one column per health outcome-age-sex.

Applies only to 2020-2022 data.

library(targets)

library(openxlsx)
library(data.table)
library(cli)

We have a variable number of missing values in our first rows of data, so we’ll need to ensure they don’t get read as logical NAs. To prevent this, the following wraps our CSV reader:

read_csv_nonlogical <- function(filepath){

  spec <- spec_csv(filepath) 

  spec$cols %>% 
    purrr::map(function(x){
      if("collector_logical" %in% class(x)){return(col_number())
      } else{return(x)}
    }) -> spec$cols
  
  read_csv(filepath, 
    col_types = spec) %>% 
    return
  
}
process_csv_safely <- function(csv_path, drop_cols = c("organisationunitcode", "orgnaisationunitdescription")) {
  stopifnot(length(csv_path) == 1L, file.exists(csv_path))
  
  cli_alert_info(paste("Working on:", csv_path))
  
  # Read file with type-safe reader
  temp_df <- read_csv_nonlogical(csv_path)
  
  # Drop the extra columns if they exist
  temp_df <- temp_df %>%
    select(-any_of(drop_cols))
  
  # Optional: check for duplicate records
  dups <- temp_df %>%
    filter(duplicated(select(., organisationunitid, periodname)))
  
  cli_alert_info(paste("Successfully created dataframe for", csv_path, "with shape", nrow(temp_df), "x", ncol(temp_df)))
  cli_alert_info(paste("Number of duplicate clinic-month-year records:", nrow(dups)))
  
  # Convert all description fields, if any, to character.
  temp_df |>
    mutate(
      across(
        contains("description", ignore.case = TRUE),
        as.character
      )
    )
}

process_csv_safely() intentionally accepts exactly one path and never holds other input tables in memory. _targets.R selects the RMA_W3_FULL paths and defines a dynamic map() branch for each path outside this notebook. That makes each CSV independently schedulable and prevents a single worker from holding every parsed table before aggregation. Dynamic branching enables parallel execution; the approved Slurm allocation and selected targets backend determine how many branches run concurrently.
